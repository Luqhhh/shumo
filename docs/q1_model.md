# Q1 模型卡（候选，等待 H-M 批准）

状态：`proposed`，对应 `D_MODEL_Q1` 仍为 pending。  
本卡是 A 形成的候选模型，不是已批准模型，也不代表已选定求解器。

## 1. 适用性

- 数据：附件 1 给定单日电价、负载、光伏预测，以及共享附录 1 参数。
- 时间：已批准的 `D_TIME_INTERNAL`，144 个十分钟区间，145 个状态边界。
- 电池：已批准的 `D_EFF` 与 `D_STATE`。
- 信息：已批准的 `D_INFO`；Q1 使用附件 1 的所有给定信息。
- Q1 case 不依赖 `D_SETTLE`、`D_RESAMPLE` 或 `D_INFO` 以外的调整/预报决策。

## 2. 索引与参数

对 `k = 0, ..., 143`：

- `price_k`：电价，元/kWh。
- `load_k`：负载电量，kWh，`load_k = load_kw_k / 6`。
- `pv_k`：光伏预测电量，kWh，`pv_k = pv_kw_k / 6`。
- `c_k`：母线侧充电量，kWh。
- `d_k`：母线侧放电量，kWh。
- `g_k`：计划购电量，kWh。
- `u_k`：实际消纳的光伏电量，kWh，`0 <= u_k <= pv_k`；未消纳部分视为弃光，不产生售电收入。
- `E_k`：区间开始时电池内部储能，kWh；`E_0` 和 `E_144` 为状态边界。

内部 `reference_day` 需要显式指定。候选：使用 `2025-01-01` 作为内部坐标，因为题面在该日期给出 `E_0=6000 kWh`；它不是附件 1 的观测日期声明。

## 3. 决策变量

连续非负变量：

```text
g_k >= 0
c_k >= 0
d_k >= 0
0 <= u_k <= pv_k
```

状态变量：

```text
1200 <= E_k <= 10800
E_0 = 6000
E_144 = 6000
```

互斥二进制变量 `z_k ∈ {0,1}`，用于禁止同时充放电。

## 4. 约束

供需关系：

```text
g_k + d_k + u_k = load_k + c_k
```

即购电、放电和实际消纳光伏需要覆盖负载和充电；余电光伏可选择弃光。  
不允许售电，因此没有额外售电收益项。

电池动态：

```text
E_{k+1} = E_k + 0.9*c_k - d_k/0.9
```

功率限制（母线侧）：

```text
0 <= c_k <= M
0 <= d_k <= M
M = 5000 kW * (1/6) h = 833.333... kWh
```

互斥：

```text
c_k <= M * z_k
d_k <= M * (1 - z_k)
```

## 5. 目标函数

```text
min sum_k price_k * g_k
```

即最小化计划购电费用。Q1 未引入紧急购电与调整购电。

## 6. 求解器候选（需团队选择）

当前仓库未声明 Q1 求解器，模型卡不能代替团队选择。

候选方案：

1. **推荐：SciPy `scipy.optimize.milp`（HiGHS）**
   - 能直接表达 `z_k` 互斥约束；
   - 需要新增 `scipy` 依赖并更新 `uv.lock`；
   - 适合 144 区间小规模 MILP。
2. `pulp` + CBC 或其他经批准的 MILP/LP 求解器；
3. 若团队论证 LP 松弛可保证不出现同时充放电，才可退回纯 LP；不能解完后手工删除某个方向。

未得到团队选择前，不添加任何求解器依赖，不实现 A4。

## 7. 输出

求解成功时生成：

- 每区间 `planned_purchase_kwh`、`action.charge_kwh`、`action.discharge_kwh`、状态轨迹；
- 全天购电量和购电费；
- 表 1、表 2 所需的同源内部摘要；
- `CaseResult.intervals` 144 段；
- 独立复算验证，不直接信任 solver 返回值。

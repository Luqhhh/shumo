## 必须修改

### R1 — P1：冻结规则阻止 Q3 合法调整

位置：`configs/decisions.toml:51–55,178–184`。

D_MPC 将“已提交”作为冻结条件，D_SETTLE 又规定只有未执行、未提交的未来时隙可以调整。但当天计划在00:00已提交，按字面执行，06:00、12:00、18:00将没有可调整的当天合同量。

应区分“历史版本不可修改”和“未来交付量可按规则新增调整版本”。已执行时隙永久冻结；Q2当天计划禁止日内修改；Q3在指定发布时刻对尚未开始且规则允许的时隙追加版本。还需明确发布、调整、执行的先后顺序及允许调整的当天范围。

验收建议：00:00提交当天计划后，06:00能够对当日未来时隙产生新版本，但不能改写旧版本或已执行时隙；普通十分钟MPC更新不能修改合同量。

### R2 — P1：能量账本重复计算弃光

位置：`configs/decisions.toml:190–197`。

S_PV被定义为已消纳光伏，却又在等式右侧加入弃光。以可用光伏100、消纳60、弃光40、负载60、其他量均为0为例，当前公式得到60=60+40。

应统一为以下一种口径：

- 左侧使用可用光伏，右侧包含弃光，并明确“可用光伏=消纳光伏+弃光”；
- 左侧使用已消纳光伏，右侧不再重复加入弃光。

模型供需约束仍须满足 `grid_supplied_kwh + discharge_kwh + pv_kwh >= load_kwh + charge_kwh`。物理账本可以采用含正确非负余量的等式，但不能强迫消纳、增加购电或伪造供给以凑平。

### R3 — P1：Q2 调整增量与调整后总量混淆

位置：`configs/decisions.toml:182–184,222`；共享接口参见 `IntervalResult.adjusted_purchase_kwh`、`PurchasePlan.adjusted_kwh`。

D_MODEL_Q2写“调整购电变量固定为0”，而D_SETTLE规定 `q_adjusted=q_plan`；共享接口中adjusted表示调整后的总量。若实现把总量置零，紧急购电公式会把已计划购买的电量再次计入短缺。

必须明确：Q2调整增量为0，最终确认总量等于计划量。Q4-2同理。

验收建议：计划购电100、负载100、其他供给及电池动作均为0时，Q2紧急购电应为0，adjusted总量应为100，调整费用为0。

### R4 — P2：整日缺失可以通过输入完整性检查

位置：`src/microgrid/problem/q2_inputs.py:236–254`。

`_require_complete_days`只检查已经出现的日期。反例中三个输入表仅包含2025-01-01和2025-01-03，加载得到288个区间，且 `require_matching_q4_2_grid` 通过；缺失的2025-01-02未被识别。

应提供预期日期集合或连续日期检查；正式入口还应验证初始化期及正式运行期覆盖。允许小样本测试时可显式传入预期范围，不能从观察到的日期反推出“完整”。

验收建议：共同缺失中间整日、共同缺失首末日期、单表缺日均应在相应范围检查中报错。

### R5 — P2：当前价格可见性与交易价格索引尚未统一

位置：`src/microgrid/problem/q2_inputs.py:435–444`；`configs/decisions.toml:100–103,149–169`。

适配器设置价格 `available_at=price.end`；D_PRICE_FORECAST写“当前价格可见”，D_SETTLE使用发布时刻交易价。反例中，06:00最后可见的是[05:50,06:00)价格1035，而[06:00,06:10)价格1036到06:10才可见。

必须明确06:00调整使用哪一个价格、00:00边界如何映射、相应价格何时公布。当前发现是接口与草案尚未统一，并非已经证实未来信息泄漏。不能通过直接提前释放整段实际数据来修补，须由团队先确认当前交易价与区间结算价的具体含义。

### R6 — 实现前置：补齐新增决策的审批依赖

位置：新增 `D_MPC`、`D_TERMINAL`、`D_YEAR_BOUNDARY`、`D_PRICE_FORECAST`、`D_LOAD_FORECAST` 与现有 `src/microgrid/cases.py`、`src/microgrid/approvals.py` 的衔接。

现有case依赖未纳入这些新增事项。将来仅批准原有D_MODEL_*和D_SETTLE，dispatcher不会检查新增卡的状态，可能在新增事项仍为proposed时使用其语义。

应按case实际依赖接入审批检查；Q4-2仍不应依赖D_RESAMPLE。当前runner尚未实现，本次没有发现实际越权运行，此项是进入模型实现前需要补齐的接口条件。

验收建议：任一case所需新增决策仍为proposed时，对应运行入口保持阻断；不依赖该决策的case不被误阻断。测试只能在临时fixture中构造批准状态，不修改真实决策批准记录。

## 建议修改

### S1：补齐逐版累计定义与往返调整算例

明确：

```text
q_final_t = q_plan_t + sum_v(delta_plus_vt - delta_minus_vt)
adjustment_cost = sum_v,t(adjustment_cost_vt)
```

对于100→80→100，最终净调整为0，但在当前草案且各交易价均为p时，调整费为40p。需防止用最终净差额取代逐版收费，并明确账本中的delta是逐版值还是累计值。

### S2：区分题面事实与结算解释

题面明确要求正常购电费用按计划量计算，并给出紧急5倍、减少50%、增加1.5倍比例。以下不能视为题面唯一明确给出的公式：相对上一版逐次计费、减少部分保留全部原计划费再加违约费、交易价按预报发布时间取值等。

这些解释应继续保持proposed，由团队核对算例后人工确认。报告不替团队选择替代公式。

### S3：为真实数据证据补齐可复现链路

文档明确报告版本加权降低RMSE但略增MAE，不宣称普遍改善，这一表述可以接受。但本分支没有提供足以独立复现全部指标的脚本和完整运行记录，本次未验证指标本身。

真实数据上的误差特征不等于周周期组合加AR(1)、24小时MPC、终端价值或年度末6000 kWh硬约束已经有效。需保存数据哈希、训练截止时间、样本范围、可见版本、参数与指标定义；滚动预测重复目标点也应明确统计口径。

### S4：更新B侧文档的状态与历史结论

`docs/b_decision_evidence.md` 和 `docs/b_model_card.md` 仍将已批准D_STATE/D_INFO写作proposed，将多个现为proposed的事项写作pending，并保留“decisions配置无差异”的旧结论。应以当前配置为准，区分历史记录和当前状态；模板导出批准范围也需区分Q1与其他case。

### S5：同步最新共享核心后验证集成

审核分支尚未包含基线main中的 `a6817b7`（发布门槛、导出证据链与容差修正）及 `d791adc`。进入实现前应同步最新共享核心，并验证集成结果。本次未执行合并。

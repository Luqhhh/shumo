# C 线附件 3 版本组合复核证据

本文只复核 `VERSION-B + WEIGHT-B + HISTORY-A` 的计算语义和预测误差，
不批准 `D_MODEL_Q3`，也不把任何 `epsilon` 自动选为正式参数。

## 复核问题

对同一个未来整点 `valid_time`，在决策时刻可能已经发布了多个附件 3
预测版本。复核比较以下候选：

- `latest_only`：只取决策时刻最新可见版本；
- `simple_average`：对全部可见版本等权平均；
- 历史 MAE 倒数权重；
- 历史 MAE 平方倒数权重，即当前讨论中的 `WEIGHT-B`。

所有方法使用完全相同的 32,028 个“决策时刻—未来整点”样本，评价从
2025-02-01 00:00 开始。每个候选版本必须满足
`issue_time <= decision_time`；历史误差只使用
`valid_time <= decision_time`、因而在当前时刻已经实现并可观察的实际 PV。

## `WEIGHT-B` 的精确定义

设同一目标时刻的可见预测版本集合为 `V(t, v)`。某版本 `j` 的提前量为
`lead_hours(j)`，先在相同提前量的因果历史上计算：

```text
MAE_h(t) = mean(|forecast - actual|)
           over records with lead_hours = h
           and valid_time <= decision_time

raw_weight_j = 1 / (MAE_lead_hours(j)(t) + epsilon_kw)^2
weight_j     = raw_weight_j / sum(raw_weight)
combined     = sum(weight_j * forecast_j)
```

`HISTORY-A` 使用从已有历史起点到当前决策时刻的扩展历史；
`HISTORY-C-56` 使用 `(decision_time - 56 days, decision_time]` 的历史作敏感性。
主分组键是 `lead_hours`；`issue_clock + lead_hours` 作为额外诊断，避免在没有
证据时悄悄改变分组粒度。

`epsilon_kw` 必须严格大于 0。复核发现早期某些历史 MAE 恰好为 0，若
`epsilon_kw = 0`，平方倒数会发生除零，因此 0 不是可执行候选。具体采用
0.1、1、5 或 10 kW，仍需团队结合稳定性和可解释性人工确认。

## 官方数据复算结果

输入核对：附件 2 实际 PV 共 52,560 个十分钟记录；附件 3 共 35,040 条预测、
1,460 个发布时间，发布时间仅为 00:00 / 06:00 / 12:00 / 18:00；同一未来
整点最多有 4 个历史发布版本。

| 方法 | MAE (kW) | RMSE (kW) | Bias (kW) |
|---|---:|---:|---:|
| 最新可见版本 | 191.8320 | 447.9712 | -32.3933 |
| 可见版本简单平均 | 194.7053 | 440.5392 | -50.3469 |
| 平方倒数、lead 分组、扩展历史、epsilon=0.1 | 171.1144 | 415.1550 | -39.4348 |
| 平方倒数、lead 分组、扩展历史、epsilon=1 | 171.1229 | 415.1551 | -39.4764 |
| 平方倒数、lead 分组、扩展历史、epsilon=5 | 171.1743 | 415.1653 | -39.6594 |
| 平方倒数、lead 分组、扩展历史、epsilon=10 | 171.2663 | 415.1987 | -39.8830 |
| 平方倒数、lead 分组、56 日历史、epsilon=1 | 171.4841 | 415.7321 | -39.4603 |

以 `epsilon=1 kW` 为复现示例，`WEIGHT-B + HISTORY-A` 相对最新可见版本的
MAE 下降 20.7091 kW（10.80%），RMSE 下降 32.8161 kW（7.33%）。这支持
“平方倒数加权值得作为主候选”，但不证明某个 `epsilon` 唯一最优：在
0.1–10 kW 范围内结果很接近，应保留参数敏感性。

按 Q3 每 6 小时发布一次新预报的节奏拆开后，结果如下：

| 当前版本提前量 | 最新可见版本 MAE (kW) | 平方倒数、扩展历史、epsilon=1 MAE (kW) |
|---|---:|---:|
| 1–6 h | 57.5078 | 51.5619 |
| 7–12 h | 149.6218 | 117.7223 |
| 13–18 h | 231.2562 | 186.2670 |
| 19–24 h | 329.2784 | 329.2784 |

19–24 小时处只有当前发布的一版可见，所以任何版本组合都不会改变结果；
版本加权的收益实际来自已有 2–4 个可见版本的 1–18 小时区域。对决策日期作
2,000 次配对区块 bootstrap 后，`epsilon=1` 相对最新版本的 MAE 差异 95%
区间为 [-23.3922, -18.2626] kW；负值表示平方倒数方案较好。只看实际 PV
严格大于 0 的 16,135 个样本时，两者 MAE 分别为 339.6793 和 380.7869 kW，
改善方向没有被夜间零值反转。

评估期理论上有 32,064 个小时目标，其中 32,028 个存在实际值。缺少的 36
个全在年末越界处：7–12、13–18、19–24 小时组分别缺 6、12、18 个；脚本会
显式记录，不把它们悄悄当作 0。

B 侧文档此前给出的 195.38/441.91 kW 不能由上述精确定义复现；它更接近
简单平均的结果。正式合并证据前，应以可运行脚本的公式、分组键和截止规则为准，
或由原计算方提供脚本说明差异来源。

## 可复核入口

脚本：`scripts/audit_q3_forecast_versions.py`

```text
python scripts/audit_q3_forecast_versions.py \
  --actual <附件2路径> \
  --forecast <附件3路径> \
  --epsilon-kw 0.1 1 5 10 \
  --output <本地证据JSON路径>
```

输出只保存汇总指标、样本定义和输入 SHA-256，不保存或上传原始题目数据。
相同输入重复运行应生成逐字节相同的 JSON。

这些候选都在同一份 2025 评价集上比较，因此排行榜只能用于收敛候选和发现
实现差异，不能把最小的 `epsilon` 差异写成独立样本外优势。若团队以后需要
在 0.1 与 1 kW 之间作数据驱动选择，应使用预先固定参数或滚动嵌套选择。

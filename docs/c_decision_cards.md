# C 线待表决 decision cards

用途：参赛队对 C 线三个未完全锁定的口径逐项表决。本文档只整理题面证据和推荐方案，不表示已批准，不代填 `confirmed_by` / `confirmed_at`。

## Card C-1：6:00 / 12:00 / 18:00 是否更新负载预测

- **题面证据**：C 题第 2 页问题 3 只明确“每天 0:00、6:00、12:00 和 18:00 可获得未来 24 小时整点的光伏发电功率预报”；附件 2 给全年实际负载/光伏，附件 3 只给光伏预报，题目没有提供负载预测或规定日内更新。
- **推荐口径**：选 `LF-A`：0:00 因果生成当天负载预测；6:00 / 12:00 / 18:00 允许只用当时 `InfoSet` 中已观测的负载重新校正剩余时隙，明确标为 `MODELING_ASSUMPTION`；同时保留“0:00 后不更新”的 `LF-B` 对照。
- **原因**：`LF-A` 能使用已发生的日内偏差改善剩余负载预测，仍满足因果性；保留 `LF-B` 可检验改善是否来自自建假设，避免把日内负载更新误写成题目条件。
- **对代码的影响**：由团队新增并批准 `D_LOAD_FORECAST`；共享预测接口接收 `decision_time` 和经过滤的历史信息，每版记录 `valid_time / available_at / training_cutoff / model_version / data_version`；Q2 只使用 0:00 版，Q3 按批准口径保存日内版本。

## Card C-2：Q4 决策时是否知道未来真实价格

- **题面证据**：C 题第 2 页问题 4 只说“实际上，外网的电价也是实时波动的”，并要求根据附件 4 的电价数据重新计算 Q2/Q3；附件 4 没有给出价格预测、发布时刻或“0:00 已知全天”的说明。
- **推荐口径**：选 `PRICE-A`：交易时刻的当前价格可见，未来真实价格不可见，计划使用因果价格预测，回放/结算使用实际价格；“全天未来价格已知”的 `PRICE-B` 只作 perfect-information 下界对照。
- **原因**：`PRICE-A` 更符合“实时波动”的字面语义，也避免 Q4 用未来真价优化造成信息泄漏；题意仍有歧义，因此保留 `PRICE-B` 可表明完全信息的理论改善上限，但不与主方案混用。
- **对代码的影响**：先重新确认现有 `D_INFO` 的 Price 可见性表；若选 `PRICE-A`，新增并批准 `D_PRICE_FORECAST`，Q4 计划输入只接收预测价、结算层再接收实际价；任何使用未来真价的 run 必须标记 `perfect_information=true`，不可选为主正式方案。

## Card C-3：Q3 调整费相对哪一版计划结算

- **题面证据**：C 题第 2 页问题 3 规定“计划购电量高于调整购电量的部分”按交易时刻电价的 50% 违约，反向超出部分按 1.5 倍计价，但未说多次调整时的“计划”是 0:00 原计划还是上一版；`result3.xlsx` 只有一张“计划购电量”和一张“调整购电量”表，没有 issue-time / delta 栏。
- **推荐口径**：选 `SETTLE-A`：把 0:00 计划视为版本 0，每次发布时刻将新计划与“上一版已确认计划”比较，仅对本次 delta 按本次交易时刻价格结算；同时将“最终版相对 0:00 版一次结算”的 `SETTLE-B` 作敏感性对照。
- **原因**：Q3 允许在多个预报时刻调整，Q4 中每次“交易时刻电价”还会不同；`SETTLE-A` 能保留每次交易的经济后果，避免中间调整在最终表中无痕消失。但题面确实没有明文规定，所以必须由团队选择并报告 `SETTLE-B` 的敏感性。
- **对代码的影响**：在 `D_SETTLE` 中批准比较基准；内部长表保存 `issue_time / target_slot / previous_committed_kwh / new_committed_kwh / delta_kwh / transaction_price / is_frozen`，费用层逐版累加；官方“调整购电量”工作表只导出每个时隙执行前的最终已确认量，不代替内部交易账本。

## Card C-4：附件 3 的小时预测如何转换成 10 分钟输入

- **题面与数据证据**：题面把附件 3 描述为“未来 24 小时整点的光伏发电功率预报”，没有说明这些值是一小时区间平均功率。对原始数据做语义审计时，预测值与对应整点实际功率的 MAE 为 186.63 kW；若解释成前一小时或后一小时平均功率，MAE 分别为 354.23 kW 和 447.06 kW。因此数据更支持“整点功率点值”解释，当前没有足够依据采用小时区间重叠法。
- **C 成员当前选择**：选 `RESAMPLE-LIN`：把当前决策边界上已经观测到的实际 PV 作为左端点，与未来 1～24 小时的组合预测整点依次连接，对中间 10 分钟右端点作线性插值；得到 kW 后统一乘以 `1/6` 转为区间电量 kWh。`RESAMPLE-PCHIP` 作为敏感性对照；该选择在团队确认前仍为 `proposed`。
- **原因**：在 2025-02-01 至 2025-12-31 的严格因果回测中，线性插值的 24 小时 MAE 为 182.64 kW、下次预报发布前 6 小时 MAE 为 83.15 kW；PCHIP 分别为 181.38 kW 和 80.82 kW，平均 MAE 略优，但线性插值的整体 RMSE 更低，在十分钟变化超过 250 kW 的位置也更稳。线性方法更简单、边界语义更明确，因此适合作为主方案；PCHIP 用于检验结论是否依赖插值方法。区间阶梯/重叠方法的 24 小时 MAE 超过 350 kW，不建议作为主方案。
- **对代码与测试的影响**：团队批准 `D_RESAMPLE` 后，C 线才能实现重采样器。实现必须满足：只使用 `available_at <= decision_time` 的预测版本；小时整点处精确还原组合预测值；跨午夜仍按真实 `valid_time` 连续；10 分钟功率转电量严格使用 `kWh = kW / 6`；不得把“线性插值”误写成能量守恒的小时平均值拆分。测试应覆盖整点命中、中间线性值、跨午夜、未来版本不可见和单位换算。该回测只比较预测层误差，不代表 Q3 最终购电成本。

每位成员独立回复选项和一句理由，再开始讨论：

```text
C-1：LF-A / LF-B；理由：
C-2：PRICE-A / PRICE-B；理由：
C-3：SETTLE-A / SETTLE-B；理由：
C-4：RESAMPLE-LIN / RESAMPLE-PCHIP；理由：
```

各项达成共识后，再由参赛队逐项更新对应 decision；不批量改为 `approved`。
